# Deploying SE-EWRS on free tiers

```
Browser ──HTTPS──▶ Cloudflare Pages      static React build (VITE_API_BASE_URL baked in)
   │
   └──HTTPS──▶ Render free web service   FastAPI + uvicorn, one instance
                     │  TLS, server certificate and host name verified
                     ▼
               Aiven free MySQL 8.4      database se_ewrs, user se_ewrs_app
```

| Part | Service | What the free tier gives (per the provider's docs) |
|---|---|---|
| Frontend | Cloudflare Pages | Static hosting; 500 builds/month; serves `index.html` for unknown paths, so deep links work |
| API | Render web service | 750 instance hours/month; sleeps after 15 min idle, ~1 min to wake; no persistent disk |
| Database | Aiven for MySQL | 1 CPU, 1 GB RAM, 1 GB disk, 76 connections, backups, no time limit, no card; may be powered off when inactive |

GitHub Actions (`.github/workflows/`):

| Workflow | When | What |
|---|---|---|
| `ci.yml` → test jobs | every push to main and every pull request | backend tests; MySQL 8.0 **and** 8.4 containers: load all scripts, run every analytics query, parity, HTTP smoke test; frontend tests, lint, build |
| `ci.yml` → `deploy-api` | push to main, all test jobs green | asks Render to deploy that exact commit, then waits until `/health` reports that commit **and** a connected database |
| `ci.yml` → `deploy-web` | after `deploy-api` succeeds | builds with the API's URL, refuses a bundle with demo credentials or a local address, publishes to Pages, checks `/` and deep links return 200 |
| `keepalive.yml` | every 10 minutes | pings `/health`, keeping Render awake and the database active |

Pull requests, forks included, run only the test jobs, which use no
secrets. Deploy jobs are skipped until the repository variable
`API_BASE_URL` exists, so pushing before setup does not fail CI.

## One-time setup

### 1. Database (Aiven)

1. Create a free **Aiven for MySQL** service. Under *Connection
   information*, download the **CA certificate**.
2. Keep the admin connection outside the repository, readable only by you:

   ```bash
   mkdir -p ~/.config/se-ewrs && chmod 700 ~/.config/se-ewrs
   mv ~/Downloads/ca.pem ~/.config/se-ewrs/aiven-ca.pem
   cat > ~/.config/se-ewrs/aiven.env <<'EOF'
   DB_ADMIN_HOST=<host from Aiven>
   DB_ADMIN_PORT=<port from Aiven>
   DB_ADMIN_USER=avnadmin
   DB_ADMIN_PASSWORD=<password from Aiven>
   EOF
   chmod 600 ~/.config/se-ewrs/aiven.env
   ```

3. Check the server supports everything the project needs. This only
   creates and drops a throwaway `se_ewrs_probe` database:

   ```bash
   cd backend
   ./.venv/bin/python -m scripts.init_remote_db \
       --admin-env ~/.config/se-ewrs/aiven.env --ca ~/.config/se-ewrs/aiven-ca.pem --probe-only
   ```

   A managed MySQL with binary logging refuses triggers and stored
   functions to a user without SUPER unless `log_bin_trust_function_creators`
   is on (`ERROR 1419`). This project needs both, so if the probe reports
   that error, this database cannot host it as-is.

4. Initialize. The script refuses to run if `se_ewrs` already has any
   table, so it can never reset data:

   ```bash
   ./.venv/bin/python -m scripts.init_remote_db \
       --admin-env ~/.config/se-ewrs/aiven.env --ca ~/.config/se-ewrs/aiven-ca.pem --demo-data
   ```

   `--demo-data` loads the fictional demo dataset and then gives every
   account its own random password, because the seed's shared password is
   published in the README. Omit it for an empty database; note the app has
   no other way to create the first administrator yet. The app account
   `se_ewrs_app` gets SELECT, INSERT, UPDATE, DELETE and EXECUTE on
   `se_ewrs` only. Every generated password goes to
   `~/.config/se-ewrs/deployment-credentials.txt` (mode 600); none is
   printed.

### 2. API (Render)

1. Render dashboard → **New → Blueprint** → this repository. It reads
   `render.yaml` and asks for:

   | Variable | Value |
   |---|---|
   | `DB_HOST`, `DB_PORT`, `DB_PASSWORD` | from `deployment-credentials.txt` |
   | `DB_SSL_CA` | the whole contents of `aiven-ca.pem` |
   | `CORS_ORIGINS` | the Pages URL, e.g. `https://se-ewrs.pages.dev` |

   `SECRET_KEY` is generated by Render. Before creating it, check that
   `region` in `render.yaml` is near the Aiven region (it cannot change
   later).
2. Service → **Settings → Deploy Hook**: copy the URL (it is a secret).
3. Open `https://<service>.onrender.com/health`; it should report
   `"database": "connected"`.

### 3. Frontend (Cloudflare Pages)

1. Workers & Pages → Create → Pages → **Direct Upload**; name the project
   (e.g. `se-ewrs`). Its URL is `https://<project>.pages.dev`.
2. My Profile → API Tokens → custom token with **Account → Cloudflare
   Pages → Edit**. Note the **Account ID**.

### 4. GitHub

Settings → Environments → create **`production`** (optionally require a
reviewer) and add its **secrets**:

| Secret | Value |
|---|---|
| `RENDER_DEPLOY_HOOK_URL` | Render's deploy hook URL |
| `CLOUDFLARE_API_TOKEN` | the Pages token |
| `CLOUDFLARE_ACCOUNT_ID` | the account ID |

Settings → Secrets and variables → Actions → **Variables** (repository
level, because a job's `if:` cannot see environment variables):

| Variable | Value |
|---|---|
| `API_BASE_URL` | `https://<service>.onrender.com` (no trailing `/api`) |
| `FRONTEND_URL` | `https://<project>.pages.dev` |
| `CLOUDFLARE_PAGES_PROJECT` | the Pages project name |

`VITE_*` values are compiled into the public bundle: only the API's
address and a timeout are ever passed that way.

Then push to main, or re-run the CI workflow: the deploy jobs run once the
tests pass.

## Verifying a deployment

```bash
API=https://<service>.onrender.com; SITE=https://<project>.pages.dev
curl -s "$API/health"                       # status ok, database connected, commit = deployed SHA
curl -s -o /dev/null -w '%{http_code}\n' "$SITE/students"   # 200: deep links work
curl -s -o /dev/null -w '%{http_code}\n' -X POST "$API/api/auth/login" \
     -H 'Content-Type: application/json' \
     -d '{"email":"admin@se-ewrs.edu","password":"Demo@12345"}'   # 401: published password refused
cd backend && ./.venv/bin/python -m scripts.api_smoke_test "$API" \
     --accounts ~/.config/se-ewrs/deployment-credentials.txt      # roles, RBAC, 401/403, lockout
```

The smoke test locks two demo accounts and one made-up email for 15
minutes. Add `--allow-writes` only against a disposable database.

## Changing the schema later

There is no migration tool. `schema.sql` drops every table, so it must
never be re-run against the live database.

- Views, procedures and triggers are replaced without touching data:
  re-apply `views.sql`, `procedures.sql` or `triggers.sql`.
- A table change needs a hand-written `ALTER TABLE` script, tried first
  on a copy (the CI MySQL job is a good place), and a backup taken first.

## Backup and restore

Aiven takes backups of the free service. For a copy you control:

```bash
mysqldump --ssl-mode=VERIFY_IDENTITY --ssl-ca=~/.config/se-ewrs/aiven-ca.pem \
  -h <host> -P <port> -u avnadmin -p --single-transaction --routines --triggers \
  --set-gtid-purged=OFF se_ewrs > se_ewrs-$(date +%F).sql
```

Restoring into a fresh, empty `se_ewrs`: `mysql ... se_ewrs < file.sql`.

## Rolling back

- **API:** Render dashboard → the service → Events → pick an earlier
  deploy → *Rollback*. Or revert the commit and push; CI redeploys.
- **Frontend:** Cloudflare Pages → the project → Deployments → an earlier
  one → *Rollback to this deployment*.
- Rolling back code never changes the database.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| Login says the request timed out | The API was asleep; wait a minute. Check the keep-alive workflow is enabled. |
| Browser console: CORS error | `CORS_ORIGINS` on Render does not exactly match the Pages URL (scheme, no trailing slash). |
| `/health` says `"database": "unavailable"` | Wrong `DB_*` values, `DB_SSL_CA` missing or truncated, or the Aiven service powered off (power it on in the console). |
| `ERROR 3159 … insecure transport` | `DB_SSL_CA` not set: the server requires TLS. |
| `deploy-api` times out | Render build failed (see its logs) or the deploy hook URL is wrong. |
| Every user locked out together | `TRUSTED_PROXY_HOPS` is 0 behind Render, so all callers share the proxy's address. |
| Deploy jobs never run | `API_BASE_URL` repository variable missing, or the push was not to main. |

## Limits worth knowing

- One API instance: the login limiter counts in memory and resets when it
  restarts. Do not scale to several instances without a shared store.
- Render's 750 hours cover one always-on service; a second would sleep.
- Aiven's free plan has no SLA and can be moved or powered off with notice.
- GitHub pauses scheduled workflows after 60 days without a commit.
